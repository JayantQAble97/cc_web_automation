# HDFC homepage suite

Uses the existing Playwright configuration, testBase, page-object and locator pattern. BOBCARD files and URLs remain supported. HDFC is configured in cc.config.yaml; use the targeted npm script so unrelated legacy suites are not run against HDFC.

```powershell
npm.cmd run test:shopstacc:hdfc:uat:homepage -- --workers=1 --retries=0
```

Tests run with fresh guest contexts by default because homepage browsing is public. For authenticated runs, set `HDFC_MOBILE` and `HDFC_OTP` in the environment. Credentials are not stored in repository files. TC_HOME_036 always keeps its clean guest session. The supplied account was independently checked through Get OTP / Verify and returned to the storefront with signed-in initials.

Verified selectors are exported as `HdfcHomePageLocators` from `HomePageLocators.ts`. HDFC methods and tests live in `HdfcHomePage.ts` and `HdfcHomePage.test.ts` to avoid replacing the existing BOBCARD implementation.

Observed requirement differences:

- TC_HOME_012: actual menu name is Mobiles & Tablets. Its Samsung link has href `/`, so it cannot satisfy filtered-listing navigation.
- TC_HOME_018: the camera-phone banner links to `/products?brand=samsung-brand` and that navigation works, but the creative has no Shop Now text/button. The strict CTA assertion fails rather than reporting generic image navigation as full coverage.
- TC_HOME_023: validates homepage name, visible price fields, struck-through MRP, discount arithmetic, monthly EMI label and a positive EMI smaller than the price. Removed the unsupported comparison with a PDP financing plan: the card does not state tenure/APR, so the two monthly amounts cannot be assumed to represent the same terms. Exact EMI calculation is not covered; it requires matching financing-term test data.
- TC_HOME_003/025/036: matching search suggestions, product identity navigation and guest browsing/login prompt passed in the unauthenticated run.

Reports are generated by the existing reporters in `playwright-report/` and `reports/test-results.json`. Failure artifacts are in `test-results/`.
